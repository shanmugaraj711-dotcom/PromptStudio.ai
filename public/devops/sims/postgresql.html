About this simulation

Practice version of the PostgreSQL Lab — Main Database, Standby, Failover lab. It shows the lab’s real outputs, but nothing here runs a live service. Every command is real syntax — but it only echoes fixed output, so it cannot hang or fail.

What it does: Two PostgreSQL databases on your own machine: a main one and a standby copy. Write fake orders into the main one, watch them appear on the standby, then kill the main one and promote the standby. The last part shows Patroni, the watcher that does the promotion for you.

What it does NOT do: it does not run a live service, it does not hold real data, and it does not touch your machine beyond this tab.

Your proof: Save the failover log: after the promotion, save the cluster output and the row count to proof/failover-log.txt. It proves no data was lost.

Done. Now run the real lab with Docker — the same commands, on your own machine. That is where the learning sticks.
