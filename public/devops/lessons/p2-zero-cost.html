What this is and why it matters

This lab sets up your machine and runs your first container: a small sealed box that holds one program.

In real work, programs behave differently on different machines, and that difference wastes hours of debugging.

By the end you can run a tiny web server in a box, stop and start it, save your work online, and write your first script.

What you need

  • A computer with internet.
  • Linux. If you use Windows, install WSL2 with Ubuntu first (Windows Subsystem for Linux — a way to run Linux inside Windows). If you use a Mac, the Docker steps below need Docker Desktop instead.
  • No cloud account. No card. Nothing here costs money.

Open a terminal first

  • Linux: press Ctrl+Alt+T, or find Terminal in your apps.
  • Mac: open the Terminal app.
  • Windows: after WSL2 and Ubuntu are installed, open Ubuntu from the Start menu — that window is your Linux terminal.

A note on the commands

The commands below are well-known, standard Linux commands. They are written for Ubuntu/Debian Linux. On other systems, package names and setup steps can differ — that part is unverified here, so check your system's own Docker docs if a step fails. Three words you will see in commands: sudo means "run this as the machine's administrator" (it may ask for your password); apt is Ubuntu's app installer; ~ means your home folder.

How to make a file (you will need this)

Projects and labs ask you to make files like index.html, Dockerfile, and .yml files. Two easy ways:

  1. With a text editor: type nano index.html, write your text, press Ctrl+O then Enter to save, Ctrl+X to leave.
  2. Straight from the terminal (good for short files):
Command
cat > index.html << 'EOF'
<h1>My site</h1>
<p>Learning DevOps, one project at a time.</p>
EOF

You should see: nothing — the file is written silently. That is normal. Run cat index.html to check it holds your two lines.

cat > writes what follows into the file until the EOF line. One YAML warning: YAML files use spaces for structure — never use the Tab key in a .yml or .yaml file. If a YAML file fails with a strange error, check the spaces first.

Step 1 — Check what you already have

Open a terminal and run:

Command
git --version
docker --version

You should see:

Command
git version 2.43.0
Docker version 27.5.1, build 9f9e405

Your version numbers will be different — that is fine. What matters is a version number, not an error.

If it breaks: "command not found" for either one means it is not installed — go to Step 2 for the missing one.

If both print a version number, skip to Step 3. If either says "command not found", go to Step 2 (Step 2 is Linux-terminal only — see its note).

Step 2 — Install Git and Docker (Ubuntu/Debian)

This step is for a Linux terminal only (Ubuntu/Debian directly, or WSL2 Ubuntu on Windows). On a Mac, do NOT run these commands — install Git and Docker Desktop, then go to Step 3.

Command
sudo apt update
sudo apt install -y git docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER

You should see: lines scroll past as packages download and install. At the end, your prompt comes back with no error.

If it breaks: "Unable to locate package docker.io" means the package list is stale — run sudo apt update again, then retry the install. "Permission denied" means you forgot sudo — run the command again with sudo in front.

Then close the terminal, open it again, and run:

Command
docker --version
Expected output
Docker version 27.5.1, build 9f9e405

Your version number will be different — that is fine.

If it breaks: "command not found" means the install did not finish — go back and run the four install commands again.

The usermod step lets you run Docker without typing sudo each time. It only takes effect after you open a fresh terminal (or log out and back in).

Warning: being in the Docker group effectively gives control of this Linux machine at the administrator level. Use it only on a machine you control. On a shared or work machine, follow the administrator's rules instead — Docker's rootless mode is the safer option there.

Step 3 — Prove Docker works

Command
docker run hello-world
Expected output
Hello from Docker!
This message shows that your installation appears to be working correctly.

This downloads a tiny test image and runs it once.

If it breaks: the most common cause is that Docker is not running — on a Linux terminal, run sudo systemctl start docker and try again. On Docker Desktop (Mac, or Windows outside WSL2), open Docker Desktop instead — systemctl does not apply there. If the error says "permission denied", your terminal session has not picked up the Docker group yet — run newgrp docker, or close the terminal and open it again, then retry.

Step 4 — Run your first real container

Command
docker run -d -p 8080:80 --name my-site nginx

You should see: a long container ID printed (a string of letters and numbers), then your prompt back. The container runs in the background — nothing else prints.

If it breaks: "port is already allocated" means something already uses port 8080 — stop that container first, or run with -p 8081:80 instead and open http://localhost:8081.

What this means:

  • -d — run in the background.
  • -p 8080:80 — connect port 8080 on your machine to port 80 inside the container. A port is just a numbered door for network traffic.
  • --name my-site — give the container a name you can use later.
  • nginx — a small, well-known web server program.

Now open your browser and go to http://localhost:8080. You should see the nginx welcome page. localhost means "this machine".

Step 5 — Look at it and stop it

Command
docker ps
docker stop my-site
docker ps
Expected output
CONTAINER ID   IMAGE     STATUS         PORTS                  NAMES
abc123def456   nginx     Up 5 seconds   0.0.0.0:8080->80/tcp   my-site

(Your container ID will be different — that is fine.) After docker stop, the second docker ps should no longer list my-site — your container is stopped. Other running containers may still appear. To start it again later: docker start my-site. To remove it fully: docker rm my-site.

If it breaks: if my-site still shows after the stop, wait a few seconds and run docker ps again — a stop takes a moment.

Step 6 — Make a folder for your work

Command
mkdir -p ~/devops-practice
cd ~/devops-practice

You should see: nothing — these commands print nothing when they work. That is normal.

If it breaks: "No such file or directory" means the folder name is wrong — run pwd to see where you are, then try again.

All later labs and projects in this kit live in this folder.

Step 7 — Put your work on GitHub (first time only)

The projects ask you to "push to GitHub". The first time, do this once:

  1. Make a free account on github.com, then make a new repository (a folder on GitHub that holds your project). GitHub will show you the repository's address — copy it.
  2. In your terminal, from inside your project folder, first check Git knows who you are: git config user.name and git config user.email. If either prints nothing, set them (see cheat-sheets.md — use an email you are comfortable attaching to your commits). Then run git status to see what would be staged, and make a .gitignore file first if the folder holds anything private (passwords, keys, Terraform state files) — never stage those. Then run:
Command
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin <your repository address>
git push -u origin main
Expected output
[main (root-commit) abc1234] first commit
 1 file changed, 1 insertion(+)
To https://github.com/<you>/<repo>.git
 * [new branch]      main -> main

(Your commit ID and repository address will be different — that is fine.)

If it breaks: "Permission denied" means GitHub does not know you yet — check the repository address and that you are signed in to GitHub. "src refspec main does not match any" means the commit never happened — run git status and check your files were staged.

What this means: git init starts tracking the folder, git add . stages everything, commit saves it, branch -M main names your main line of work "main", remote add origin connects your folder to GitHub, and push sends it there. After this first push, later pushes are just git add ., git commit -m "message", git push. Replace <your repository address> with the address GitHub showed you — do not type the brackets.

Step 8 — Your first script

A script is a text file full of commands. Make one that checks your Docker containers:

Command
cat > health-check.sh << 'EOF'
#!/bin/bash
echo "Running containers:"
docker ps --format "{{.Names}} is {{.Status}}"
EOF
chmod +x health-check.sh
./health-check.sh
Expected output
Running containers:
my-site is Up 2 minutes

(Your container names and times will be different — that is fine. If no containers are running, only the first line prints.)

What this means: the first line says "run this with Bash"; chmod +x makes the file runnable; ./ means "run the file in this folder".

If it breaks: "permission denied" usually means the file is not marked runnable yet — run chmod +x health-check.sh and try again. But the same error can also come from the wrong owner, a folder you cannot enter, or a disk that forbids running files. If the error names a missing interpreter instead, check the first line of the script and whether that program is installed.

If something goes wrong

  1. Read the error message fully before searching for help.
  2. docker ps -a shows stopped containers too — useful when a container died.
  3. docker logs my-site shows what a container printed before it stopped. Start with the error message and the container's status. For a container that stopped, docker logs is usually the next look. For a container that never started, the error Docker printed is the evidence — there may be no logs at all.
  4. Docker itself confused? Three different problems, three checks: docker --version prints nothing → the Docker program is missing, install it. docker ps says it cannot connect → Docker is installed but not running, start it (Linux terminal: systemctl; Docker Desktop: open the app). docker ps works but a command says permission denied → your terminal has not picked up the Docker group, run newgrp docker or open a fresh terminal.
