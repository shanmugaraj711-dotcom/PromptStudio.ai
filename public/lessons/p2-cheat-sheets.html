Cheat Sheets — Commands You Will Actually Use

Phase 2 · The Rest of DevOps

What this is and why it matters

This is your quick reference: keep it open while you practise, and look things up here when you need them.

In real work, nobody memorises every tool — the skill is knowing where to look and checking the result.

Every line pairs one tool with what it does and what good output looks like, so a wrong result stands out at once.

All commands below are standard, well-known commands for their tools, written for a Linux terminal (Ubuntu/Debian directly, or WSL2 Ubuntu on Windows). systemctl commands work on systemd Linux only — on Docker Desktop, start the app instead.

How to read this file: every line pairs a command with what it does and what good output looks like. If the output looks different, check the error decoder (Phase 1) or the troubleshooting index at the end of this file.

Reference tool
This page supports every topic — use it whenever you are stuck. It has no ladder of its own.

Making files

Try it Yourself »Open the practice terminal and run it yourself — nothing installs. Included with Phase 2. Simulation — practice version. The real thing is the same commands, in your own terminal.
Command
nano <file>            Open a file in a simple text editor
                       (Ctrl+O, Enter to save, Ctrl+X to leave)
cat > <file> << 'EOF'  Write lines into a file until the EOF line

YAML warning: use spaces, never Tab, in .yml files.

Linux

Command
pwd                    Show which folder you are in

cat <file>             Print a file's contents
grep <word> <file>     Find a word inside a file
chmod +x <file>        Make a file runnable
ps aux                 List running programs
top                    Watch live CPU and memory use
df -h                  Show disk space
free -h                Show memory use
sudo systemctl start <service>    Start a service
sudo systemctl status <service>   Check a service

Git

Command
git init               Start tracking a folder

git config user.name "Your Name"    Tell Git who you are (once)
git config user.email "you@example.com"   (once)
git status             Show what changed
git add .              Stage all changes
git commit -m "message"   Save changes with a message
git log --oneline      Show past saves, one line each
git branch             List branches
git checkout -b <name>   Make a new branch and move into it
git merge <branch>     Merge a branch into the current one
git push               Send your saves to GitHub
git pull               Download and integrate the latest changes
                       (usually merge, or rebase if set up that way)

Docker

Command
docker ps              List running containers
docker ps -a           List all containers, including stopped ones
docker images          List downloaded images
docker run hello-world   Prove Docker works
docker run -d -p 8080:80 --name web nginx
                       Run nginx in the background on port 8080
docker logs <name>     Read a container's output
docker stop <name>     Stop a container
docker start <name>    Start a stopped container
docker rm <name>       Remove a stopped container
docker build -t <name>:<tag> .   Build an image from a Dockerfile
docker exec -it <name> sh   Open a shell inside a running container
docker run -d -v ~/data:/data --name store ubuntu sleep 1000
                       Bind mount: share folder ~/data into the
                       container at /data (a bind mount, not a
                       Docker-managed named volume — files in it
                       live on your machine)
docker compose up -d   Start the containers in docker-compose.yml
docker compose ps      List containers started by Compose
docker compose down    Stop and remove Compose containers

Kubernetes (kubectl)

kubectl is the command tool for talking to a Kubernetes cluster.

Command
kubectl get pods       List pods
kubectl get nodes      List cluster machines
kubectl get deployments   List deployments
kubectl get services   List services
kubectl port-forward service/<name> 8080:80
                       Open a service in your browser
kubectl describe pod <name>   Show details about one pod
kubectl logs <pod>     Read a pod's logs
kubectl logs <pod> --previous   Read the crashed run's logs after
                       a restart
kubectl apply -f <file.yaml>   Create things from a file
kubectl delete -f <file.yaml>  Remove things from a file

Command

                       Copy a local image into the cluster

Terraform

Command
terraform init         Prepare a folder for Terraform
terraform plan         Show what Terraform would change
terraform apply        Create or change the infrastructure
terraform destroy      Remove everything Terraform created

Warning: terraform destroy removes everything the active configuration and state manage. Before you run it: check you are in the right folder, check the workspace and state, and read the destruction plan (terraform plan -destroy) first. Run it only on your own disposable practice setup — never on anything shared or real, and never without that plan check.

Prometheus and Grafana (concepts, not commands)

  • Prometheus collects numbers (metrics) from your apps.
  • Grafana turns those numbers into charts.

Kafka (Phase 1 — run inside the container with docker exec)

Command
docker exec kafka-a /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
                       List topics on cluster a
docker exec kafka-a /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic orders --partitions 1 --replication-factor 1
                       Make a topic called orders
docker exec -it kafka-a /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic orders
                       Send messages (type lines, Ctrl+C to stop)
docker exec kafka-a /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic orders --from-beginning
                       Read messages from the start

Kafka commands run inside the container because Kafka tells clients to come back to the container's own name. Do not run them from your own terminal.

PostgreSQL (Phase 1 — run inside the container with docker exec)

Command
docker exec pg-primary psql -U learner -d practice -c "SELECT * FROM orders ORDER BY id;"
                       Read rows from the primary
docker exec pg-replica psql -U learner -d practice -c "SELECT pg_is_in_recovery();"
                       t = standby, f = primary
docker exec pg-replica psql -U learner -d practice -c "SELECT pg_promote();"
                       Promote the standby to primary
docker exec pg-primary psql -U learner -d practice
                       Open an interactive psql shell (type \q to leave)

A standby refuses writes — that is correct, not a bug.

Patroni (Phase 1)

Command
curl http://localhost:8008/cluster
                       Show the cluster: who is leader, who is replica
curl http://localhost:8008/leader
                       Show the leader only

Patroni's web page answers on port 8008 (node 1) and 8009 (node 2).

Redis (Phase 1 — run inside the container with docker exec)

Command
docker exec redis-a redis-cli ping
                       Should answer PONG
docker exec redis-a redis-cli SET user:101 Asha
                       Save a value
docker exec redis-a redis-cli GET user:101
                       Read it back
docker exec redis-a redis-cli SETEX login-code:101 60 482913
                       Save a value that deletes itself after 60 seconds
docker exec redis-a redis-cli TTL login-code:101
                       Seconds left before it deletes itself
docker exec redis-a redis-cli INCR orders:count
                       Add 1 to a counter
docker exec redis-b redis-cli INFO replication
                       Check the copy is following the main store

Moto and aws (Phase 1 — object store)

Command
docker compose exec awscli aws --endpoint-url http://moto-a:5000 s3 mb s3://incoming
                       Make a bucket called incoming
docker compose exec awscli aws --endpoint-url http://moto-a:5000 s3 cp /files/receipt-001.txt s3://incoming/
                       Upload a file
docker compose exec awscli aws --endpoint-url http://moto-a:5000 s3 ls s3://incoming/
                       List files in the bucket
docker compose exec awscli aws --endpoint-url http://moto-b:5000 s3 cp s3://incoming/receipt-001.txt -
                       Print a file's contents from the second store

Troubleshooting index — error, then where to look

  • "image not found" / container never starts → break-and-fix-labs.md Lab 1: read Docker's error, check the image name and tag.
  • Container starts, then dies at once → break-and-fix-labs.md Lab 2: the main program exited; run the real foreground app.
  • Pipeline fails on a missing test file → break-and-fix-labs.md Lab 3: write the real test, do not bypass it.
  • Git merge conflict → break-and-fix-labs.md Lab 4: read the markers, pick the right lines, finish the merge.
  • Browser shows nothing but the container runs → break-and-fix-labs.md Lab 5: check the PORTS column in docker ps — the -p mapping is the door, logs alone do not prove it.
  • Docker build "file not found" → break-and-fix-labs.md Lab 6: check the build context and .dockerignore.
  • Pod crashes, bad image → kubernetes-lab.md Step 5: describe the pod, fix the Deployment, check rollout status.
  • Monitoring target DOWN → portfolio-projects.md Project 3: check docker compose ps, the service logs, then the Prometheus Targets error line, in that order.
  • Kafka topic missing or consumer shows nothing → Phase 1 kafka-lab.md: check the topic list on the right cluster, and remember Kafka commands run with docker exec inside the container, not from your own terminal.
  • PostgreSQL replica shows 0 rows → Phase 1 postgresql-lab.md: wait 10 seconds and try again, then check SELECT pg_is_in_recovery(); shows t on the replica.
  • "cannot execute INSERT in a read-only transaction" on a replica → correct, not a bug: a standby takes reads only. Write on the primary, or promote the replica first.
  • Redis READONLY error on the copy → correct, not a bug: a one-way replica takes reads only.
  • Moto file missing from the second store → Phase 1 object-store-lab.md: wait a minute, then check docker compose logs mirror for the error line.
  • Load balancer answers the same backend every time → Phase 1 load-balancer-lab.md: check docker compose ps — a dead backend is skipped by the guard, which is correct behaviour.
