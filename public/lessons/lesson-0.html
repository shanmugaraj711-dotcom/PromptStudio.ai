Lesson 0: Before the Terminal

Free

What this is and why it matters

This lesson is the setup step: it gets your computer ready before any real lab begins.

Without it, every later lab fails at the first step, because the tools it needs are not installed or not running.

You will learn the basic words, install one free program, and run two quick checks that prove it works.

This lesson is for a true beginner. If you have never used a terminal, never installed Docker, and do not know what Linux or Ubuntu is, start here. Do this lesson first. Then go to Phase 1.

One idea per step. Do the steps in order. Do not skip ahead.

1. What these words mean

Computer. The machine on your desk or in your lap. It runs programs, stores your files, and shows you the screen.

Operating system. The main program that runs your computer. It starts when you switch the machine on. It lets your other programs use the screen, the keyboard, and the files. Windows and macOS are operating systems.

Linux. An operating system, like Windows and macOS, but free and open. Many servers run Linux. You do not need to learn Linux to start this kit. You only need to know the word.

Ubuntu. One version of Linux. It is the most common version people start with. When a guide says "Ubuntu", it means a computer running this version of Linux.

Terminal. A window where you type commands instead of clicking. It looks plain: a dark or white window with a line of text waiting for you to type. Every command in this kit runs in a terminal.

Command. One line of typed text that tells the computer to do one thing. For example, docker --version is a command. It asks Docker to tell you which version it is. You type it, press Enter, and the computer answers.

Docker. A free program that runs other programs for you, each one in its own sealed box. You install Docker once. Then every lab in this kit runs inside Docker.

Container. One sealed box that Docker runs. A container holds one program and everything that program needs. When you stop the container, the program stops. When you start it again, the program starts again.

Image. The recipe Docker uses to build a container. An image is a saved copy of a program, ready to run. Docker downloads the image once, then builds containers from it. For example, the image postgres:16-alpine is the recipe for a PostgreSQL database.

Port. A numbered door on your computer. Programs listen at doors. When a lab says "PostgreSQL is on port 5432", it means the database answers at door number 5432 on your own machine. Two programs cannot use the same door at the same time.

File. One saved thing: a lesson, a picture, a list of orders. A file has a name, like docker-compose.yml.

Folder. A place that holds files, like a drawer holds papers. A folder has a name, like kafka-lab. Folders can hold other folders too.

cd. Short for "change directory". The command that moves your terminal into a folder. For example, cd phase1 moves your terminal into the phase1 folder. You type it, press Enter, and you are inside that folder. To go back up one folder, type cd .. and press Enter.

2. Installing Docker

You need Docker before any lab will run. Install it once.

On Windows

  1. Open your web browser and go to the Docker website. Search for "Docker Desktop" and open the download page.
  2. Download Docker Desktop for Windows.
  3. Open the downloaded file and follow the installer. Accept the normal choices it offers.
  4. The installer sets up WSL for you. WSL is a built-in part of Windows that lets Linux programs run on Windows. You do not need to set it up yourself. Docker does it.
  5. Restart your computer if the installer asks you to.
  6. Open Docker Desktop from the Start menu. Wait until it says it is running. The first start takes a few minutes.
  7. Leave Docker Desktop running in the background while you do the labs.

To open a terminal on Windows, open Git Bash. It comes with Git for Windows: download Git for Windows, install it, then find Git Bash in the Start menu. Run every command in this kit in Git Bash, not in PowerShell. The kit's commands (including for loops and .sh scripts) work in Git Bash. They do not work in PowerShell.

On Mac

  1. Open your web browser and go to the Docker website. Search for "Docker Desktop" and open the download page.
  2. Download Docker Desktop for Mac. Pick the download that matches your Mac: Apple chip, or Intel chip. If you do not know which one you have, click the Apple menu, then "About This Mac", and read the chip name.
  3. Open the downloaded file and follow the installer. Accept the normal choices it offers.
  4. Open Docker Desktop from your Applications folder. Wait until it says it is running. The first start takes a few minutes.
  5. Leave Docker Desktop running in the background while you do the labs.

To open a terminal on a Mac, open the Terminal app. You can find it in Applications, inside the Utilities folder. Or press Command and Space together, type "Terminal", and press Enter.

3. First checks

Open your terminal. Type each command exactly as shown, then press Enter.

First, check Docker itself:

Try it Yourself »Open the practice terminal and run it yourself — nothing installs. Free. Simulation — practice version. Run the real lab with Docker to do it for real.
Command
docker --version
Expected output
Docker version 27.5.1, build 9f9e405

Your version number will be different — that is fine. What matters is a version number, not an error.

If it breaks: "command not found" means Docker is not installed — go back to section 2 and install it. "Cannot connect to the Docker daemon" means Docker Desktop is not running yet — open Docker Desktop and wait until it says it is running.

Next, check Compose, the tool that starts several containers together from one file:

Command
docker compose version
Expected output
Docker Compose version v2.32.4-desktop.1

Again, your version number will be different — that is fine.

If it breaks: if you see an error, Docker Desktop may still be starting. Wait a minute and try again. If it says "compose is not a docker command", your Docker is too old — update Docker Desktop to the newest version.

If both commands show a version number, Docker is ready.

4. What is inside your downloaded zip

This kit is a hands-on learning environment that lets you practice real DevOps tasks directly on your own computer.

You download it so you can run databases, message queues, and deployment setups locally without paying for cloud servers or risking breaking live production systems.

Inside your download, you will find lab folders containing ready-to-run setup recipes, step-by-step Markdown lessons, and proof template files to record your completed work.

If you hit an issue while running a lab, a built-in doctor script checks your machine health, and an error decoder shows you how to resolve common failures.

When you unzip the Phase 1 kit, you get a folder called phase1. Inside it you will see:

  • Lesson files, one per topic: start-here.md, kafka-lab.md, postgresql-lab.md, redis-lab.md, object-store-lab.md, load-balancer-lab.md, end-to-end-lab.md, and this file, lesson-0.md. There is also error-decoder.md: when a command fails, look up the error there.
  • One folder called portfolio. It holds a README template and blank proof forms. When a lab says "save your proof", the proof goes in there.
  • One folder per lab: kafka-lab, postgresql-lab, redis-lab, object-store-lab, load-balancer-lab, and end-to-end.
  • Inside postgresql-lab there is one more folder, patroni, for the Patroni part of that lab.
  • Each lab folder has a file called docker-compose.yml. That file is the list of containers for that lab. You do not need to read it or change it. The lab steps tell you the commands to run in each folder.
  • Two helper scripts: kit-doctor.sh and reset.sh. The next section says what they do.

Do your work inside the phase1 folder. When a lab says "go into the lab folder", it means open your terminal, move into that folder, and run the commands there.

5. If you get stuck

Do these three steps, in order.

Step 1 — Run the kit doctor script. In your terminal, move into the phase1 folder with cd phase1, press Enter, then run:

Command
bash kit-doctor.sh

It checks Docker, the doors (ports) the labs need, free disk space, and free memory. For each check it prints OK, or a plain-English FIX line that tells you what to do.

You should see:

Command
OK: Docker command found.
OK: Docker Compose works.
OK: Docker is running.
OK: Port 5432 is free (needed by postgresql-lab).
OK: Disk space is fine (about 12 GB free).
OK: Memory is fine (about 8 GB free right now).

Your lines will name the checks and numbers on your machine — what matters is OK on every line, not the exact words.

If it breaks: "No such file or directory" means you are not inside the phase1 folder — run cd phase1 first, then try again. A FIX line means that one check failed — do what the FIX line says, then run the script again.

Step 2 — Look up the error in the error decoder. Copy the error message from your terminal, find it in the decoder, and follow the fix it gives.

Step 3 — Email us. If the doctor says all OK and the error decoder has no match, email support@promptstudioai.in with the exact error line and the step you were on. We reply within 24 hours.

If Lesson 0 worked, you are ready for Phase 1.
