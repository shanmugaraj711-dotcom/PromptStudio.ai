Lesson 0: Before the Terminal

Free

What this is and why it matters

This lesson is the setup step: it gets your computer ready before any real lab begins.

Without it, every later lab fails at the first step, because the tools it needs are not installed or not running.

You will learn the basic words, install one free program, and run two quick checks that prove it works.

This lesson is for a true beginner. If you have never used a terminal, never installed Docker, and do not know what Linux or Ubuntu is, start here. Do this lesson first. Then go to Phase 1.

Think of it like this. You want to cook in a new kitchen. First you need a stove that works. This lesson is switching the stove on and checking the flame. The cooking comes later.

One idea per step. Do the steps in order. Do not skip ahead.

1. What these words mean

Read these first. Every word below is used in the steps that follow, and none of them is explained again later.

Computer. The machine on your desk or in your lap. It runs programs, stores your files, and shows you the screen.

Operating system. The main program that runs your computer. It starts when you switch the machine on. It lets your other programs use the screen, the keyboard, and the files. Windows and macOS are operating systems.

Linux. An operating system, like Windows and macOS, but free and open. Many servers run Linux. You do not need to learn Linux to start this kit. You only need to know the word.

Ubuntu. One version of Linux. It is the most common version people start with. When a guide says "Ubuntu", it means a computer running this version of Linux.

Terminal. A window where you type commands instead of clicking. It looks plain: a dark or white window with a line of text waiting for you to type. Every command in this kit runs in a terminal.

Command. One line of typed text that tells the computer to do one thing. For example, docker --version is a command. It asks Docker to tell you which version it is. You type it, press Enter, and the computer answers.

Docker. A free program that runs other programs for you, each one in its own sealed box. You install Docker once. Then every lab in this kit runs inside Docker.

Container. One sealed box that Docker runs. A container holds one program and everything that program needs. When you stop the container, the program stops. When you start it again, the program starts again.

Image. The recipe Docker uses to build a container. An image is a saved copy of a program, ready to run. Docker downloads the image once, then builds containers from it. For example, the image postgres:16-alpine is the recipe for a PostgreSQL record store. The 16 is the version number of PostgreSQL. The word alpine means a small, light version of the recipe.

Docker Desktop. The version of Docker you install on Windows and Mac. It is a normal app with an icon. You open it, and it runs Docker in the background for you.

WSL. Short for Windows Subsystem for Linux. It is a built-in part of Windows that lets Linux programs run on Windows. You do not set it up yourself. The Docker installer sets it up for you.

Git. A tool that keeps track of changes to files. You do not need to learn Git in this lesson. You only need one small part of it on Windows: Git Bash, the terminal that comes with Git.

Git Bash. A terminal program for Windows that comes with Git for Windows. It understands the kit's commands. PowerShell is a different Windows terminal. The kit's commands do not work in PowerShell, so do not use PowerShell for this kit.

Port. A numbered door on your computer. Programs listen at doors. When a lab says "PostgreSQL is on port 5432", it means the record store answers at door number 5432 on your own machine. Two programs cannot use the same door at the same time.

File. One saved thing: a lesson, a picture, a list of orders. A file has a name, like docker-compose.yml.

Folder. A place that holds files, like a drawer holds papers. A folder has a name, like kafka-lab. Folders can hold other folders too.

Compose. A tool that starts several containers together from one file. That file is called docker-compose.yml. It is the list of containers for one lab.

Daemon. A background program that keeps running without a window. When an error says "cannot connect to the Docker daemon", it means Docker Desktop is not running yet, so there is no background Docker program to talk to.

cd. Short for "change directory". The command that moves your terminal into a folder. For example, cd phase1 moves your terminal into the phase1 folder. You type it, press Enter, and you are inside that folder. To go back up one folder, type cd .. and press Enter. The two dots mean "the folder above this one".

The kit. The set of folders and lesson files you downloaded for this course. After you unzip it, the Phase 1 part lives in a folder called phase1.

What you need before Step 1

  • A computer running Windows or Mac. This lesson gives steps for Windows and Mac only. It gives no Linux install steps. If you use Linux, open the Docker docs link in Step 2 (https://docs.docker.com/get-started) and follow the Linux install steps there.
  • A web browser.
  • Internet, to download Docker.
  • The kit zip file, downloaded and unzipped. This lesson does not give the zip file name, because it can change. After unzipping, look in your Downloads folder for a folder called phase1. That is where your work happens.

Do not pay for anything in this lesson. Docker Desktop is free for the personal use in this kit.

Step 1 — Open a terminal

What this is: a terminal is the plain window where you will type every command in this kit.

Why we do it first: without an open terminal, you have nowhere to type the checks in Steps 3 and 4.

On Windows

First install Git for Windows, because Git Bash is your terminal.

  1. Open your web browser and go to the Git for Windows download page at https://gitforwindows.org — that is the official download page. Do not download Git from any other site.
  2. Download it, open the downloaded file, and follow the installer. Accept the normal choices it offers.
  3. Then find Git Bash in the Start menu and open it.
  4. Run every command in this kit in Git Bash, not in PowerShell.

What "accept the normal choices" means: the installer shows a series of screens with a Next button. Keep the choices it already picked, and keep clicking Next until it finishes. You do not need to change any setting.

Why Git Bash and not PowerShell: the kit's commands use for loops and .sh script files. A for loop is a command that repeats another command several times. A .sh file is a saved list of commands for the bash program. PowerShell is a different Windows terminal that does not understand those commands, so they fail there. Git Bash understands them.

On Mac

Open the Terminal app. You can find it in Applications, inside the Utilities folder. Or press Command and Space together, type Terminal, and press Enter.

Step 2 — Install Docker Desktop

What this is: Docker Desktop is the app that installs Docker on your computer.

Why we install it: every lab in this kit runs inside Docker containers. Without Docker, no lab can start.

On Windows

  1. Open your web browser and go to the Docker website at https://docs.docker.com/get-started — that page links to the official Docker Desktop download. Do not download Docker from any other site.
  2. Download Docker Desktop for Windows.
  3. Open the downloaded file and follow the installer. Accept the normal choices it offers, as in Step 1: keep the choices it already picked, and keep clicking Next until it finishes.
  4. The installer sets up WSL for you. WSL is a built-in part of Windows that lets Linux programs run on Windows. You do not need to set it up yourself.
  5. Restart your computer if the installer asks you to. If it does not ask, do not restart.
  6. Open Docker Desktop from the Start menu. Wait until it says it is running. The first start takes a few minutes. "Running" means the Docker Desktop window shows it is started, and its small icon in the bottom-right corner of your screen is steady, not flashing or showing an error.
  7. Leave Docker Desktop running in the background while you do the labs. If you close it, Docker stops, and the labs stop working. If a lab suddenly stops working, check first whether Docker Desktop is still open — if it closed, open it again, wait until it says it is running, and try the lab step again.

On Mac

  1. Open your web browser and go to the Docker website at https://docs.docker.com/get-started — that page links to the official Docker Desktop download.
  2. Download Docker Desktop for Mac. Pick the download that matches your Mac: Apple chip, or Intel chip. If you do not know which one you have, click the Apple menu, then "About This Mac", and read the chip name. If the chip name starts with "Apple M1", "Apple M2", or "Apple M3", pick the Apple chip download. If it says "Intel", pick the Intel chip download.
  3. Open the downloaded file and follow the installer. Accept the normal choices it offers, as in Step 1.
  4. Open Docker Desktop from your Applications folder. Wait until it says it is running. The first start takes a few minutes. "Running" means the Docker Desktop window shows it is started.
  5. Leave Docker Desktop running in the background while you do the labs. If you close it, Docker stops, and the labs stop working. If a lab suddenly stops working, check first whether Docker Desktop is still open.

Step 3 — Check Docker itself

What this is: a check command that asks Docker to tell you which version it is.

Why we run it: if Docker answers with a version number, Docker is installed. If it answers with an error, Docker is not installed or not running yet, and you must fix that before any lab.

Type this in your terminal, then press Enter:

Try it Yourself »Open the practice terminal and run it yourself — nothing installs. Free. Simulation — practice version. Run the real lab with Docker to do it for real.
Command
docker --version

Word by word:

  • docker — the Docker tool.
  • --version — "tell me your version number".

What you should see, line by line:

Command
Docker version 27.5.1, build 9f9e405
  • Docker version 27.5.1 — the version number of Docker on this machine. Your number will be different. That is fine.
  • build 9f9e405 — a short code that names the exact build of that version. Your code will be different. That is fine.
  • What matters: a version number appears, and no error appears. That means Docker is installed.

If it breaks:

  • command not found — Docker is not installed. Go back to Step 2 and install it.
  • Cannot connect to the Docker daemon — Docker Desktop is not running yet. Open Docker Desktop and wait until it says it is running, then try the command again.

Step 4 — Check Compose

What this is: Compose is the tool that starts several containers together from one file. You met the word in section 1. Every lab uses Compose to start its containers.

Why we run it: if Compose is missing or too old, the labs cannot start.

Type this in your terminal, then press Enter:

Command
docker compose version

Word by word:

  • docker — the Docker tool.
  • compose — the part of Docker that starts several containers together from one file.
  • version — "tell me your version number".

What you should see, line by line:

Command
Docker Compose version v2.32.4-desktop.1
  • Docker Compose version v2.32.4-desktop.1 — the version number of Compose. Your number will be different. That is fine.
  • What matters: a version number appears, and no error appears.

If it breaks:

  • Any error right after you installed Docker: Docker Desktop may still be starting. Wait one minute and try again.
  • compose is not a docker command — your Docker is too old. Update Docker Desktop to the newest version, then try again.

If both Step 3 and Step 4 show a version number, Docker is ready.

Step 5 — Find your way around the phase1 folder

What this is: a tour of the folders you unzipped, so you know where everything lives.

Why we do it: every lab tells you to "go into the lab folder". If you do not know the folder names, you cannot follow that instruction.

After you unzip the kit, you get a folder called phase1. Open it. Inside it you will see:

  • Lesson files, one per topic. Their file names are: start-here.md, lesson-0.md, kafka-lab.md, postgresql-lab.md, redis-lab.md, object-store-lab.md, load-balancer-lab.md, end-to-end-lab.md, and error-decoder.md. The lesson file names end in .md. That means they are plain text lesson files. When a lab says "look up the error in the error decoder", it means open the file phase1/error-decoder.md and find your error message there.
  • One folder called portfolio. It holds a README template and blank proof forms. When a lab says "save your proof", the proof goes in phase1/portfolio/proof/. The proof files live in that folder; the templates there end in -TEMPLATE.txt.
  • One folder per lab: phase1/kafka-lab, phase1/postgresql-lab, phase1/redis-lab, phase1/object-store-lab, phase1/load-balancer-lab, and phase1/end-to-end.
  • Inside phase1/postgresql-lab there is one more folder, phase1/postgresql-lab/patroni, for the Patroni part of that lab.
  • Each lab folder has a file called docker-compose.yml. That file is the list of containers for that lab. You do not need to read it or change it. The lab steps tell you the commands to run in each folder.
  • Two helper scripts: phase1/kit-doctor.sh and phase1/reset.sh. A script is a saved list of commands in one file. kit-doctor.sh checks your machine — the next step says what it does. reset.sh wipes one lab's data and starts it fresh. It is used at the end of a lab or a drill, when the lab tells you to run it, from the phase1 folder, like this: bash reset.sh kafka-lab.

Do your work inside the phase1 folder. When a lab says "go into the lab folder", it means: open your terminal, move into that folder, and run the commands there. Moving into a folder is the next step's first command.

Step 6 — Move into the phase1 folder

What this is: cd moves your terminal into a folder.

Why we run it: the doctor script in Step 7 lives in the phase1 folder. Your terminal must be inside that folder before you can run it.

First, move your terminal to where you unzipped the kit. If the phase1 folder is in your Downloads folder, you would first move into Downloads, then into phase1. This lesson does not give your exact starting folder, because it depends on where you unzipped the kit. Find the phase1 folder on your machine first, then move into it.

Type this, then press Enter, once you are in the folder that holds phase1:

Command
cd phase1

Word by word:

  • cd — short for "change directory". It moves your terminal into a folder.
  • phase1 — the name of the folder to move into.

What you should see: nothing special. Your terminal line now shows you are inside phase1. That is normal. To go back up one folder, type cd .. and press Enter. The two dots mean "the folder above this one".

Step 7 — Run the kit doctor script

What this is: kit-doctor.sh is a saved list of checks. It checks Docker, the numbered doors (ports) the labs need, free disk space, and free memory.

Why we run it: it finds setup problems before you start a lab, and it prints a plain-English FIX line that tells you what to do for each problem.

Type this in your terminal, while you are inside the phase1 folder, then press Enter:

Command
bash kit-doctor.sh

Word by word:

  • bash — the program that runs script files. It reads the script and runs its commands one by one.
  • kit-doctor.sh — the name of the script file. It lives in the phase1 folder. That is why you must be inside phase1 first.

What you should see, line by line:

Command
OK: Docker command found.
OK: Docker Compose works.
OK: Docker is running.
OK: Port 5432 is free (needed by postgresql-lab).
OK: Disk space is fine (about 12 GB free).
OK: Memory is fine (about 8 GB free right now).
  • Each line starts with OK: — that one check passed.
  • Port 5432 is free — door number 5432 is not used by any other program, so the PostgreSQL lab can use it. Door 5432 is the door the PostgreSQL record store listens on. If another program were already using door 5432, the PostgreSQL lab could not start, because two programs cannot use the same door at the same time.
  • Disk space is fine (about 12 GB free) — your numbers will be different. What matters is the word OK, not the exact number.
  • Memory is fine (about 8 GB free right now) — your numbers will be different. What matters is the word OK, not the exact number.
  • How to tell it worked: every line starts with OK:. If every line says OK, your machine is ready.

Your run will show more port lines than the example above. The script checks 12 doors in total: 9092 and 9094 (Kafka lab), 5432 and 5433 (PostgreSQL lab, main and standby), 6379 and 6380 (Redis lab, main and second store), 9000 and 9010 (object store lab, first and second store), 8080 (load balancer lab), and 2379, 8008 and 8009 (Patroni lab). Each one prints its own OK line. At the very end it prints one last line:

Command
All OK - your machine is ready for the labs.

If it breaks:

  • No such file or directory — you are not inside the phase1 folder. Run cd phase1 first, then try again.
  • A line starting with FIX instead of OK — that one check failed. Do what the FIX line says, then run the script again.

Step 8 — If you get stuck

Do these three steps, in order.

  1. Run the doctor script again, as in Step 7. It prints a FIX line for each problem.
  2. Look up the error in the error decoder. Copy the error message from your terminal, find it in the file phase1/error-decoder.md, and follow the fix it gives.
  3. Email support@promptstudioai.in with the exact error line and the step you were on. The team replies within 24 hours.

If Lesson 0 worked — both version checks showed a number, and the doctor script showed OK on every line — you are ready for Phase 1. Start with phase1/start-here.md.
